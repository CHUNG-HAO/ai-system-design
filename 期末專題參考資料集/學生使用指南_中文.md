## 1. 第一個觀念：`ems_cases` 是主表

大多數功能都從 `ems_cases` 開始。

| 想做的功能 | 主要資料表 | 說明 |
|---|---|---|
| 救護案件列表 | `ems_cases`、`patients`、`hospitals`、`alerts` | 顯示案件、病患年齡性別、疑似病症、送往醫院、通報狀態 |
| 救護車端病患卡片 | `ems_cases`、`prehospital_vitals`、`patients` | 顯示生命徵象、主訴、GCS、qSOFA、NIHSS、FAST |
| 醫院推薦 | `ems_cases`、`hospitals`、`hospital_resource_snapshots`、`routing_recommendations` | 依據病症、距離、醫院能力、資源快照推薦醫院 |
| 院內急救 Dashboard | `alerts`、`resource_orders`、`ems_cases`、`hospitals` | 顯示 P1/P2、ETA、ACK、尚未確認的資源 |
| 急救處置流程追蹤 | `treatment_events`、`outcomes`、`ems_cases` | 顯示到院後 CT、導管室、抗生素、外傷團隊等時間 |
| KPI 報表 | `outcomes`、`alerts`、`resource_orders`、`ems_cases` | 計算流程達標率、ACK 時間、資源準備率 |

## 2. 建議完成的功能

### 2.1 案件清單

畫面欄位建議：

- 案件代碼：`ems_cases.case_id`
- 疑似病症：`ems_cases.suspected_condition`
- 優先級：`ems_cases.priority`
- 病患年齡 / 性別：`patients.age`、`patients.sex`
- 收治醫院：`hospitals.hospital_name`
- 通報 ACK 分鐘數：`alerts.ack_minutes`
- 預估到院時間：`ems_cases.eta_time`

### 2.2 單一案件詳細頁

建議分成五個區塊：

1. 病患基本資料：`patients`
2. 救護案件資料：`ems_cases`
3. 生命徵象趨勢：`prehospital_vitals`
4. 推薦醫院排序：`routing_recommendations`
5. 院內資源需求：`resource_orders`

## 3. 建議完成的功能

### 3.1 院內急救 Dashboard

需要顯示：

- 目前 P1 案件數。
- 每件案件 ETA。
- 醫院是否已 ACK。
- 哪些資源還沒有確認。
- 快到院但資源未確認的紅燈提醒。

建議紅燈規則：

```text
若 priority = P1 且 arrival_hospital_time - 現在時間 <= 10 分鐘，
且仍有 resource_orders.request_status != 'confirmed'，
則顯示紅燈。
```

### 3.2 依病症啟動不同資源包

可用 `intervention_protocols` 說明規則，再用 `resource_orders` 顯示實際資源。

| 病症 | 建議資源 |
|---|---|
| STEMI | ED_BED、CARDIOLOGIST、CATH_LAB、ICU_BED |
| 疑似急性腦中風 | ED_BED、NEUROLOGIST、CT_ROOM、STROKE_BED |
| 敗血症 / 敗血性休克 | ED_BED、SEPSIS_NURSE、LAB_FAST_TRACK、ICU_BED、VENTILATOR |
| 重大外傷 | TRAUMA_BAY、TRAUMA_SURGEON、CT_ROOM、BLOOD_PACK、OPERATING_ROOM |
| OHCA | RESUSCITATION_BAY、EM_PHYSICIAN、VENTILATOR、ICU_BED |

## 4. 建議完成的功能

### 4.1 KPI 看板

建議 KPI：

| KPI | 用到的欄位 | 說明 |
|---|---|---|
| 平均 ACK 分鐘數 | `alerts.ack_minutes` | 醫院收到通報後多久確認 |
| 到院前 ACK 率 | `alerts.first_ack_time < ems_cases.arrival_hospital_time` | 到院前是否已有人確認 |
| 到院前資源確認率 | `resource_orders.confirmed_time < ems_cases.arrival_hospital_time` | 病人到院前資源是否已確認 |
| STEMI 達標率 | `outcomes.door_to_balloon_min <= 90` | STEMI 流程是否及時 |
| 中風 CT 達標率 | `outcomes.door_to_ct_min <= 25` | 中風 CT 是否及時 |
| 敗血症抗生素達標率 | `outcomes.antibiotic_to_recognition_min <= 60` | 抗生素是否及時 |
| 外傷團隊 ready 率 | `outcomes.trauma_team_ready_min_from_arrival <= 0` | 外傷團隊是否到院前就緒 |

### 4.2 推薦醫院解釋

不要只顯示分數，還要顯示原因：

- `reason_1`
- `reason_2`
- `reason_3`
- `selected_reason`

這樣使用者才知道系統為什麼推薦某一家醫院。

## 5. 建議完成的功能

### 題目 A：急救通報清單

請做一個頁面，列出所有 P1 案件，並依 ETA 由近到遠排序。

需要使用：

- `ems_cases`
- `alerts`
- `hospitals`

### 題目 B：單一案件病患摘要

請輸入 `case_id`，顯示該案件的：

- 病患年齡、性別、病史。
- 疑似病症與主訴。
- 初始生命徵象。
- 生命徵象趨勢。
- 推薦醫院前三名。
- 需要準備的院內資源。

需要使用：

- `patients`
- `ems_cases`
- `prehospital_vitals`
- `routing_recommendations`
- `resource_orders`

### 題目 C：醫院資源壅塞分析

請分析哪家醫院的急診壅塞指標平均最高，以及壅塞時是否影響推薦分數。

需要使用：

- `hospitals`
- `hospital_resource_snapshots`
- `routing_recommendations`

### 題目 D：流程達標率分析

請比較五種病症的 protocol target met rate，並說明哪一種病症最容易延遲。

需要使用：

- `ems_cases`
- `outcomes`
